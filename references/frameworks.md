# Frameworks: fit and misfit

Read this only when a reply fits no row in the SKILL.md table. Pick the framework whose "fits" line matches, then keep the house style.

| Framework | Structure | Fits | Misfits |
|---|---|---|---|
| BLUF | Bottom line, then evidence, then detail | Everything. It is the base layer under all others. | Never. |
| Pyramid (Minto) | Answer, 2 to 3 supporting points, evidence under each | Recommendations with several independent reasons | Single-reason answers |
| SCQA | Situation, Complication, Question, Answer | The reader does not yet feel the problem | Simple answers; problems the user raised themselves (go answer first) |
| What / So what / Now what | Event, why it matters, next step | Updates, FYIs, small incidents | Decisions with trade-offs |
| 1-3-1 | 1 problem, up to 3 options, 1 recommendation | The choice depends on the user's budget, risk appetite, or priorities | One option is clearly best (just recommend it) |
| SBAR | Situation, Background, Assessment, Request | Escalations needing action now. The **BLOCKED** report is a compressed SBAR: result, why, one ask. | Routine reports. No ask means no SBAR. |
| RYG | Red, yellow, green per item, exceptions first | 3 or more parallel items | A single item, or anything needing nuance |
| Commander's intent | Purpose, key tasks, end state | Plans: the reader approves the outcome, not the steps | Reporting finished work |
| Incident update | Impact, state, current action, next update time | Long-running or failing work | One-shot tasks |
| Inverted pyramid | Most important first, cuttable from the bottom | Long answers, teaching, exploration | Already-short replies |
| Narrative memo (Amazon style) | Decision, context, evidence, analysis, recommendation, risks | Large strategic decisions delivered as a document | Chat replies. Use type 10: cover note plus document. |

## The information hierarchy

Whatever the framework, answer in this order and stop as early as possible:

1. What do you need me to know?
2. Why should I care?
3. Do you need something from me?
4. What evidence supports this?
5. What more is available if I ask?

## Phrasing for recommendations

- Name the decider: "Your call. I recommend B."
- Make yes cheap: "Say go and I'll do B." An agent cannot act on a timer, so never promise "at 14:00 unless you object". Irreversible, destructive, or paid actions always need an explicit yes.
- When the user overrides you: state the cost once, then commit. "Going with A. Cost: about 2 extra hours."

## When brevity is wrong

Risk, irreversible actions, errors, skipped scope, legal or safety caveats, and low confidence are never compressed away. Shorten the sentence, keep the fact, and move it to line 2.
